    What Crucible does

    Crucible takes new colleagues from zero to productive. Trainings live in git: readings, quizzes and hands-on labs. People, teams, budgets and settings live in Crucible's own database. One Go server runs everything and serves the web app.

    Trainees

    Learn

    • The Hearth: your trainings, progress, rank and badges
    • Readings, then quizzes scored at once (choice, exact, pattern, order, match) or by a person (written, upload, live sign-off)
    • Modules in order or free, as the training sets
    • Ranks from Ore to Masterwork, which only ever rise; a badge per finished training
    Trainees

    Labs

    • Tasks on the left, tabbed terminals on the right, a Check per task
    • Hints that can cost points; break-fix scenarios prepared by setup scripts; Reset scenario
    • A timer, an idle prompt, one extension, recorded terminals
    • Three places to run: laptop, cluster, AWS (below)
    Scorers, mentors, leaders

    Score and follow

    • The Anvil: written answers, uploads, lab reviews and self-reported labs, with rubrics; return for rework
    • Journey: each person and training as heat cells, with flags for who may be stuck
    • Mentor page; email and Slack/Teams notifications
    Approvers, leaders, admins

    Spend safely

    • Every lab is priced before it runs; cost tiers decide who approves
    • Escalation up the tiers inside schedule hours
    • Monthly team and program budgets, alerts at 80%, hard caps; budgets fail closed
    • Schedules, a kill switch, and the Ledger of estimates and real AWS bills
    Admins

    Run the forge

    • Forge settings, teams, rosters and Manage trainings, all audited
    • Move this forge: export to one file, import into a fresh instance
    • Sign-in through Keycloak or Cognito; one admin to start
    • AWS deployment on one k3s node that sleeps outside working hours
    Authors

    Write trainings

    • A plain git repo: training.yaml, modules/…
    • crucible lint and crucible preview on your machine
    • An editor in Crucible: drafts become edits on their own branch, reviewed, then merged by the bot
    • Programs can pin a training to an exact content version

    Laptop labs

    runtime: local

    The trainee runs crucible-agent. It holds an outbound connection to Crucible and runs the lab's Docker Compose file on the laptop. Free, so never needs approval. Checks run on the trainee's machine, so results are self-reported; a program can ask a scorer to review them.

    Cluster labs

    runtime: cluster

    Each lab gets its own Kubernetes namespace on Crucible's cluster: one pod (sysbox in production) runs the Compose file, with a quota and a deny-by-default network policy. Nothing to install. Priced by the platform's hourly rate; unset means unavailable, never free.

    AWS labs

    runtime: aws

    Real resources in a shared AWS lab account, built by Terraform with credentials scoped to one lab, priced with infracost, and always approved by a person. Explained in full below.

    How cloud labs work

    An AWS lab is a Terraform module in the training repo plus tasks and check scripts. Crucible never lets it run without a price, a person's approval and a way to clean up everything it made. Here is one lab's life.

    1. The trainee asks

      The lab page shows an estimate: infracost prices the lab's Terraform per hour, times the lab's time limit. A lab above its own max_hourly_usd, or in a region this Crucible doesn't allow, can't be requested.

    2. A person approves

      AWS labs never start on their own. The estimate picks the tier: program approver, team leader, then admin. A request that would pass a team or program budget cap needs an admin, as an audited override. Unanswered requests move up a tier after the escalation hours, counted only inside the program's schedule.

    3. Credentials for one lab

      Crucible assumes the lab role with AWS STS, tagging the session crucible:lab-id=<id>. The one-hour credentials are refreshed for as long as the lab runs. A permission boundary limits them to EC2 and S3, small instance types and the allowed regions; IAM refuses any create without the lab's own tag, and any change to another lab's resources.

    4. Terraform builds it

      In the lab's namespace on Crucible's cluster, a tf-apply pod runs terraform apply. Crucible adds its own crucible.tf to the module: an S3 state backend keyed by the lab id, and the AWS provider with default tags crucible:lab-id, crucible:team and crucible:training. Modules may not declare their own provider or backend.

    5. The trainee works

      A workspace pod with the AWS CLI, Terraform and kubectl backs the terminals. Checks and setup scripts run there with the lab's credentials, out of the trainee's sight. The pods can't reach the node's metadata service, so they can never borrow the node's role.

    6. It ends, and is cleaned up

      The time limit, the idle timeout, the schedule closing, a budget cap, End lab or the kill switch all end it the same way: terraform destroy, then a tag sweep deletes anything else carrying the lab's id, including what the trainee made by hand and instances with termination protection.

    7. The reaper checks hourly

      Anything tagged with a lab that ended over an hour ago is deleted. Resources tagged with a lab Crucible doesn't know, and untagged creates seen in CloudTrail, are reported to admins instead.

    8. The real bill arrives

      Every six hours Crucible reads Cost Explorer, grouped by the crucible:* cost-allocation tags. The Ledger shows a running lab's estimate, switches to the AWS bill once it settles (24–48 hours), and tracks estimate against actual.

    The guardrails

    Tags are compulsory
    EC2 creates without crucible:lab-id are denied, lab tags can't be removed, and every instance must use the lab's own security group.
    Small and close
    Small instance types, gp3 volumes of limited size, allowed regions only, no dedicated tenancy, no IAM.
    Budgets fail closed
    If Crucible can't read spend, it starts nothing. A running lab ends when its cost would reach a cap.
    Isolation is best effort
    Labs share one account. Trainees can read account-wide Describe calls and their own Terraform state, so use a dedicated sandbox account and keep secrets out of state.

    Before you start

    Run every command from the repo root. Docker Desktop needs about 8 GiB. Run one heavy suite at a time: two local stacks share a compose project and collide.

    trainee
    takes trainings
    senior
    scores, mentors, maintains
    leader
    leads The Forge, approves
    admin
    runs the forge

    Passwords equal the user name. The app is at http://localhost:8080. Keycloak listens on 8081 unless you set KEYCLOAK_PORT (use another port if 8081 is taken).

    Real money is only in phase 9.Every other phase runs on your machine with fakes. Never point the local scripts at real AWS: Terraform here runs only with mock providers.

    9b · Cloud labs on a real AWS sandbox

    This creates real resources and costs real money.Use a dedicated sandbox account and a deployed Crucible (crucible aws init, then crucible aws up). The full commands and every must-fail case are in docs/runbooks/aws.md.

    • With lab-account credentials:

      go run ./cmd/crucible aws labs-init --region eu-west-1

      Expectthe lab role, permission boundary and state bucket, and account-wide S3 Block Public Access. Back up deploy/aws/labs/terraform.tfstate.

      1. In the payer account, activate cost-allocation tags crucible:lab-id, crucible:team, crucible:training (after the first lab; up to 24 hours).
      2. Open Cost Explorer once in the lab account.
      3. infracost auth login; put the key in crucible.tfvars as infracost_api_key.
      4. Run crucible aws up on the machine that holds the labs state.

      ExpectAWS labs switch on; without the key, requests say no estimate is available.

    • Request and approve it, then in the workspace terminal:

      aws sts get-caller-identity
echo hi > f && aws s3 cp f s3://crucible-lab-$CRUCIBLE_LAB_ID/forged.txt

      Expectassumed-role/crucible-lab/crucible-lab-<id>; both tasks pass with Check; on the node, tf-apply completed and lab running.

    • Positive controls first: a dry-run t3.micro launch with the lab's tags and own security group returns DryRunOperation. Then each must fail:

      • a volume with no lab tag, another lab's id, or the tag key in other letter case
      • an instance in the default security group, a t3.large, dedicated tenancy, an io2 or oversized volume
      • removing lab tags, a bucket not named crucible-lab-<id>…, a region outside the allowed list
      • reading another lab's Terraform state, aws iam list-roles, reaching the metadata service

      ExpectAccessDenied or UnauthorizedOperation for every one, and DryRunOperation for the positive controls.

    • Create a tagged volume by hand in the workspace, then End lab.

      Expectwithin about 5 minutes the lab is cooled and the Ledger shows the volume as end-of-lab sweep / deleted; nothing tagged with the lab id is left (terminated instances stay listed about an hour; that is AWS).

    • With admin credentials, create one volume tagged with a lab that ended over an hour ago and one tagged cccccccccccc. Ledger → Refresh now.

      Expectthe first is deleted, the second reported and kept, and admins get one email.

    • Run a lab with a 2-hour limit; after 65 minutes run aws sts get-caller-identity again.

      Expectit still works.

    • After the boundary tests, Ledger → Refresh now; look up a create in CloudTrail event history.

      Expectno CloudTrail finding (every successful create was tagged); the user name is the session name crucible-lab-<id>.

    • In your sandbox content repo, add the runbook's terraform/ec2.tf (a t3.nano, its own security group, a data volume) next to Cloud Heat's main.tf.

      Expecta non-zero infracost estimate; the instance, both volumes and the rules carry crucible:lab-id; End lab destroys everything with no failed findings.

    • 24–48 hours later: Ledger → Refresh now.

      Expectthe lab's row shows its AWS bill without (so far), and Estimate vs actual counts it.
