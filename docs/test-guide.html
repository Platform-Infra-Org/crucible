    What Crucible does

    Crucible takes new colleagues from zero to productive. Trainings live in git: readings, quizzes and hands-on labs. People, teams, budgets and settings live in Crucible's own database. One Go server runs everything and serves the web app.

    Trainees

    Learn

    • The Hearth: your trainings, progress, your craft (smith rank), your swords and badges
    • Readings, then quizzes scored at once (choice, exact, pattern, order, match) or by a person (written, upload, live sign-off)
    • Modules in order or free, as the training sets
    • A sword per training, from Ore to Masterwork, and a smith rank from experience, from Bellows Hand to Grandmaster; both only ever rise; a badge per finished training
    Trainees

    Labs

    • Tasks on the left, tabbed terminals on the right, a Check per task
    • Hints that can cost points; break-fix scenarios prepared by setup scripts; Reset scenario
    • A timer, an idle prompt, one extension, recorded terminals
    • Three places to run: laptop, cluster, AWS (below)
    Scorers, leaders

    Score and follow

    • The Anvil: written answers, uploads, lab reviews and self-reported labs, with rubrics; return for rework
    • Journey: each person and training as heat cells, with flags for who may be stuck
    • Journey; email and Slack/Teams notifications
    Approvers, leaders, admins

    Spend safely

    • Every lab is priced before it runs; cost tiers decide who approves
    • Escalation up the tiers inside schedule hours
    • Monthly team and program budgets, alerts at 80%, hard caps; budgets fail closed
    • Schedules, a kill switch, and the Ledger of estimates and real AWS bills
    Admins

    Run the forge

    • Forge settings, teams and their tags, connected repositories, training roles for people and groups, Manage trainings, all audited
    • Move this forge: export to one file, import into a fresh instance
    • Sign-in through Keycloak or Cognito; one admin to start
    • AWS deployment on one k3s node that sleeps outside working hours
    Authors

    Write trainings

    • A plain git repo: training.yaml, modules/…
    • crucible lint and crucible preview on your machine
    • An editor in Crucible: drafts become edits on their own branch, reviewed, then merged by the bot
    • Programs can pin a training to an exact content version

    Laptop labs

    runtime: local

    The trainee runs crucible-agent. It holds an outbound connection to Crucible and runs the lab's Docker Compose file on the laptop. Free, so never needs approval. Checks run on the trainee's machine, so results are self-reported; a program can ask a scorer to review them.

    Cluster labs

    runtime: cluster

    The trainee's agent installs the lab's Helm charts into their own namespace on a cluster they pick from their kubeconfig (kind on the laptop, or a remote one). Terminals and scripts run in a toolbox container. Free, and results are self-reported.

    AWS labs

    runtime: terraform · cloud: aws

    Real resources in a shared AWS lab account, built by Terraform with credentials scoped to one lab, priced by Crucible from AWS list prices, and always approved by a person. Explained in full below.

    How cloud labs work

    An AWS lab is a Terraform module in the training repo plus tasks and check scripts. Crucible never runs one without a price, a person's approval and a way to clean up everything it made. Phases 9a and 9b check each stage:

    1. Ask and approve

      The trainee sees an estimate and requests the lab; a person at the right cost tier approves.

    2. Build and work

      Crucible assumes a role scoped to this one lab, and Terraform builds it. The trainee works in a workspace pod.

    3. End and clean up

      terraform destroy, a tag sweep, and an hourly reaper for anything left.

    4. Settle the bill

      The Ledger shows the estimate, the metered cost, then the billed cost once it settles.

    How it is built is in an AWS lab, start to finish. The roles are in IAM roles, and what the boundary forbids is in the IAM fence. Deploying the labs stack is in AWS labs setup. Labs share one account, so use a dedicated sandbox and keep secrets out of Terraform state. For our own account, which has one account and no inbound path, see what differs in our account.

    Before you start

    Run every command from the repo root. Docker Desktop needs about 8 GiB. Run one heavy suite at a time: two local stacks share a compose project and collide.

    trainee
    takes trainings
    senior
    scores and edits
    leader
    leads The Forge, approves
    admin
    runs the forge

    Passwords equal the user name. The app is at http://localhost:8080. Keycloak listens on 8081 unless you set KEYCLOAK_PORT (use another port if 8081 is taken).

    Real money is only in phase 9.Every other phase runs on your machine with fakes. Never point the local scripts at real AWS: Terraform here runs only with mock providers.
